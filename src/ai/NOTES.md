# AI 감지 파트 메모 (한웅)

> 노션 "AI 감지 파트 (한웅)" 페이지를 옮긴 문서입니다. (2026-11-02 기준)
> 감지 분류 확장과 IF-01 형식은 **제 쪽 초안**이고 팀 확정이 아닙니다. 팀이 합의한 통신 규격은 [`docs/design.md`](../../docs/design.md) 이고, 서버도 그 규격대로 만들었습니다.

딴짓 보호 로봇에서 카메라 쪽을 맡고 있습니다. 노트북 웹캠으로 화면 앞에 뭐가 있는지 보고, 그 결과를 서버로 넘기는 부분까지가 제 담당이에요. 화면 바꾸는 건 채웅, 앱은 채연, 로봇 움직이는 건 유나가 합니다.

처음 기획 때는 사람만 잡으려고 했는데, 회의하다 보니 휴대폰이나 동물, 위험한 물건도 구분하면 시연이 더 재밌을 것 같아서 범위를 조금 넓혔습니다. 아직 팀 확정은 아니고 제 쪽 초안입니다.

## 뭘 감지하나

웹캠 한 프레임에서 아래 여섯 가지 중 하나로 정리해서 보냅니다.

| 분류 | 코드 값 | 예시 | 비고 |
| --- | --- | --- | --- |
| 사람 | `person` | 화면 앞에 사람이 들어옴 | 누구인지는 구분 안 함 (얼굴 인식 X) |
| 휴대폰 | `phone` | 손에 든 휴대폰 | 딴짓 감지용으로 넣었음 |
| 동물 | `animal` | 강아지, 고양이, 새 | 집에서 시연할 때 반려동물 때문에 오작동하는 거 막으려고 |
| 위험물 | `danger` | 칼, 가위 | 아래 한계 부분 꼭 읽어주세요 |
| 물건 | `object` | 컵, 책, 가방, 노트북 등 | 위 네 개에 안 들어가는 나머지 |
| 없음 | `none` | 빈 화면 | 카메라는 정상인데 잡힌 게 없을 때 |

카메라가 안 켜지거나 중간에 끊기면 `none`이 아니라 `unknown`으로 따로 보냅니다. "아무것도 없음"이랑 "볼 수가 없음"은 다른 거라서요.

### 모델 클래스랑 어떻게 묶었나

사전학습된 객체 감지 모델(COCO 80개 클래스 쓰는 YOLO 계열 생각 중)을 그대로 쓰고, 클래스를 위 분류로 묶는 방식입니다. 새로 학습시키는 건 시간상 안 할 생각이에요.

- `person` ← person
- `phone` ← cell phone
- `animal` ← dog, cat, bird, horse, sheep, cow 등 동물 클래스 전부
- `danger` ← knife, scissors
- `object` ← 나머지 클래스 전부

모델은 아직 최종으로 안 정했습니다. 정하면 이름이랑 버전, 라이선스를 평가 카드에 적을게요.

### 여러 개가 같이 잡히면

사람이 휴대폰 들고 있으면 둘 다 잡히니까 대표 분류를 하나 정해야 합니다. 일단 이 순서로 했어요.

```
danger > phone > person > animal > object > none
```

위험물이 제일 위인 건 놓치면 안 되는 거라서고, 휴대폰이 사람보다 위인 건 휴대폰이 잡히면 사람도 거의 같이 있어서 휴대폰 쪽이 정보가 더 많기 때문입니다. 대표값만 보내는 게 아니라 잡힌 목록 전체도 같이 보내니까, 화면이나 로봇 쪽에서 다르게 쓰고 싶으면 그 목록 보고 판단하면 됩니다.

## 서버로 보내는 형식 (초안, 서버 미반영)

IF-01을 이렇게 고쳤습니다. 원래 `state`가 detected / not_detected 위주였는데 분류가 늘어서 `label` 필드를 추가했어요.

```json
{
  "v": 1,
  "kind": "state_change",
  "event_id": "evt_20261030_0012",
  "state": "detected",
  "label": "phone",
  "prev_label": "person",
  "objects": [
    {"label": "phone", "class": "cell phone", "conf": 0.81},
    {"label": "person", "class": "person", "conf": 0.93}
  ],
  "detected_at": "2026-10-30T15:00:00+09:00",
  "source": "laptop_webcam",
  "reason": null
}
```

- `state`: `detected`(뭔가 잡힘) / `not_detected`(none) / `unknown`(카메라 문제)
- `label`: 위 우선순위로 고른 대표 분류 하나
- `objects`: 이번 판정에서 잡힌 것 전부. 좌표랑 이미지는 안 넣습니다
- `reason`: `unknown`일 때만 채움 (`camera_open_failed`, `frame_timeout`, `model_not_ready`)

대표 분류(`label`)가 바뀔 때만 보내고, 안 바뀌면 몇 초에 한 번 살아있다는 신호(`heartbeat`)만 보낼 생각입니다. 몇 초로 할지는 아직 못 정했어요.

지금 서버(`src/server`)는 `docs/design.md` ① 형식(`type`, `timestamp`, `confidence`)만 받습니다. 이 초안을 쓰려면 design.md 고치는 PR로 팀 합의부터 해야 해요.

## 분류별로 뭐가 반응할지 (팀이랑 정할 것)

제 담당은 아니지만 이벤트 받는 쪽이 정해야 해서 제 생각만 적어둡니다.

| 분류 | 화면 (채웅) | 로봇 (유나) | 기록 (채연) |
| --- | --- | --- | --- |
| person | 가짜 엑셀로 전환 | 인사 | 남김 |
| phone | ? | ? | 남김 |
| animal | 전환 안 함 | 안 움직임 | 남김 |
| danger | 경고 문구? | 안 움직임 | 남김 |
| object / none | 그대로 | 그대로 | 안 남겨도 될 듯 |

물음표는 회의 때 정하면 됩니다. 위험물 잡혔을 때 로봇이 움직이면 오히려 위험할 수 있어서 저는 멈추는 쪽이 맞다고 봐요.

### 라즈봇 `/greet` 응답 처리

로봇 인사(`/greet`)를 부르면 응답이 두 가지로 옵니다.

| 상황 | 응답 | 처리 |
| --- | --- | --- |
| 인사함 | `{"ok": true}` | 성공 |
| 쿨다운 중 (마지막 인사 후 10초 안) | `{"ok": true, "skipped": "cooldown"}` | 성공 (에러 아님) |

둘 다 `ok: true`라서 성공으로 처리하면 됩니다. `skipped`가 있어도 재시도하거나 에러 로그 남기지 않아요. 로봇 쪽에 이미 10초 쿨다운이 있으니까, 제 쪽 쿨다운 시간 정할 때도 이거랑 겹치는지 같이 보면 될 것 같습니다.

## 한계 (중요)

- 위험물은 칼이랑 가위 정도만 됩니다. 모델이 원래 아는 클래스에 총, 불, 라이터 같은 건 없어요. 그런 걸 잡으려면 데이터 모아서 따로 학습해야 하는데 이번 범위에선 안 합니다.
- 시연용이라 실제 안전 장치로 쓰면 안 됩니다. 칼을 못 잡을 수도 있고, 볼펜을 칼로 잡을 수도 있어요.
- 휴대폰은 화면이 보이게 들고 있을 때 잘 잡히고, 책상에 엎어놓거나 손에 가려지면 놓치는 경우가 많을 것 같습니다. 실제로 해보고 결과 적을게요.
- 사람이 누구인지는 모릅니다. 선생님이든 친구든 다 `person`이에요.
- 노트북 CPU로 돌리면 느릴 수 있어서 해상도를 낮추거나 몇 프레임마다 한 번씩만 돌릴 수도 있습니다.

## 1. 전체 구조 — 웹 서버가 "중앙 허브"

```
 [AI · 한웅]                [웹 서버 · 채웅]                  [로봇 · 유나]
 웹캠 사람 감지  ──POST──▶  /api/events  ──POST /greet──▶  라즈봇 인사 + 음성
                            (기록 저장)
                               ▲      ▲
                       GET 0.5초마다   GET 2초마다
                               │      │
                     [웹 화면 · 채웅]  [앱 · 채연]
                     엑셀 화면 전환    알림 + 감지 기록
```

- **AI는 웹 서버 한 곳에만** 신호를 보냅니다. 로봇·웹·앱으로 나눠주는 건 서버가 합니다.
- 통신은 전부 **HTTP + JSON** 하나로 통일합니다. (입문자 친화적, `curl`·브라우저로 바로 테스트 가능)
- 실시간 푸시(WebSocket 등) 대신 **주기적으로 물어보기(polling)** 를 씁니다. 시연에는 0.5초면 충분합니다.

### 누가 서버이고 누가 클라이언트인가

| 모듈 | 역할 | 하는 일 |
|---|---|---|
| 🌐 웹 서버 (채웅) | **서버** (포트 8000) | 이벤트 받기·저장, 로봇에 명령, 상태·기록 제공 |
| 🦾 로봇 (유나) | **서버** (포트 5000) | `/greet` 명령을 받으면 인사 |
| 🧠 AI (한웅) | 클라이언트 | 웹 서버에 이벤트 보내기만 함 |
| 🖥️ 웹 화면 (채웅) | 클라이언트 | 웹 서버에 상태 물어보기 |
| 📱 앱 (채연) | 클라이언트 | 웹 서버에 기록 물어보기 |

### 왜 MQTT 브로커나 P2P가 아니라 중앙 서버인가
- **P2P (각자 직접 연결)**: AI가 로봇·웹·앱 3곳 주소를 모두 알아야 하고, 하나만 꺼져도 AI 쪽 오류 처리가 복잡해짐 → ❌
- **MQTT 브로커**: 구조는 깔끔하지만 브로커(Mosquitto) 설치와 라이브러리 학습이 추가됨. 개발 기간 4일·입문자 위주라 부담 → 보류
- **중앙 웹 서버 (HTTP)**: 어차피 웹 서버가 필요하고 감지 기록 저장도 서버가 해야 함. `curl`·브라우저로 바로 테스트 가능 → ✅ 채택

### 메시지 형식 공통 규칙
- 모든 요청·응답 본문은 **JSON**, 헤더 `Content-Type: application/json`
- 필드 이름은 **소문자 snake_case** (`event_id`, `person_detected`)
- 시간은 모두 **ISO 8601 + 한국 시간** (`2026-11-02T14:03:21+09:00`)
- 성공 응답은 `{ "ok": true, ... }`, 실패 응답은 `{ "ok": false, "error": "이유" }`

| 항목 | 값 |
|---|---|
| 네트워크 | 모든 기기가 **같은 Wi-Fi** (11/2엔 한 사람 핫스팟으로 통일) |
| 웹 서버 | `http://<서버 노트북 IP>:8000` — **채웅 노트북**에서 실행 (11/2 당일 채웅이 IP를 단톡에 공유) |
| 로봇 | `http://<라즈봇 IP>:5000` |
| 주소 설정 | IP는 코드에 박지 말고 **설정 파일/변수**로 빼기 (장소 바뀌면 IP가 바뀜) |
| 시간 형식 | ISO 8601, 한국 시간 — 예: `2026-11-02T14:03:21+09:00` |

## 3. API 목록

### ① AI → 웹 서버: 감지 이벤트 보내기
`POST /api/events`
```json
{
  "type": "person_detected",
  "timestamp": "2026-11-02T14:03:21+09:00",
  "confidence": 0.87
}
```
| 필드 | 설명 |
|---|---|
| `type` | `"person_detected"` (사람 나타남) 또는 `"person_left"` (사람 사라짐) |
| `timestamp` | 감지 시각 |
| `confidence` | 감지 신뢰도 0~1 (선택) |

응답: `{ "ok": true, "id": 12 }`

**AI 쪽 규칙** (신호 폭주 방지)
- 사람이 **2초 이상 연속** 보이면 `person_detected` **한 번만** 보냄
- 사람이 **3초 이상 안 보이면** `person_left` 한 번 보냄
- 같은 상태를 반복해서 보내지 않음

### ② 웹 서버 → 로봇: 인사 명령
`POST http://<라즈봇 IP>:5000/greet`
```json
{ "event_id": 12 }
```
응답: `{ "ok": true }`
- 서버는 `person_detected` 를 받으면 로봇에 이 요청을 보냄
- **타임아웃 2초**. 로봇이 꺼져 있어도 서버/웹/앱은 정상 동작해야 함
- 로봇은 인사 중에 또 요청이 오면 무시 (**쿨다운 10초**)

`GET http://<라즈봇 IP>:5000/health` → `{ "ok": true }` (연결 확인용)

### ③ 웹 화면 → 웹 서버: 현재 상태 확인 (0.5초마다)
`GET /api/status`
```json
{ "state": "present", "since": "2026-11-02T14:03:21+09:00" }
```
- `state` 가 `"present"` → 엑셀 화면, `"absent"` → 원래 화면

### ④ 앱 → 웹 서버: 감지 기록 가져오기 (2초마다)
`GET /api/events?date=2026-11-02` → 그날 이벤트 목록
```json
[
  { "id": 12, "type": "person_detected", "timestamp": "2026-11-02T14:03:21+09:00", "confidence": 0.87 },
  { "id": 13, "type": "person_left",     "timestamp": "2026-11-02T14:03:40+09:00", "confidence": null }
]
```
- 새 알림 판단: 마지막으로 본 `id` 보다 큰 `person_detected` 가 생기면 알림

`GET /api/stats?date=2026-11-02` → `{ "date": "2026-11-02", "count": 7 }` (그날 감지 횟수)

## 4. 혼자 테스트하는 법 (하드웨어·다른 모듈 없이)

| 담당 | 테스트 방법 |
|---|---|
| AI | 서버 없이도 돌아가게, 보낼 JSON을 콘솔에 출력하는 모드 |
| 웹 서버 | `curl` 로 AI 흉내: `curl -X POST localhost:8000/api/events -H "Content-Type: application/json" -d "{\"type\":\"person_detected\",\"timestamp\":\"2026-11-02T14:03:21+09:00\"}"` |
| 로봇 | `curl -X POST <라즈봇IP>:5000/greet` 로 단독 테스트 |
| 웹 화면·앱 | 서버가 없으면 위 JSON 예시를 고정값(가짜 데이터)으로 넣고 개발 |

> **원격 기간(10/31~11/1)** 엔 각자 집에 있어서 서로의 기기에 접속할 수 없습니다(같은 Wi-Fi가 아님).
> 이 기간엔 위 방법으로 **각자 단독 테스트**하고, **실제 연동은 11/2 오프라인 모임**에서 합니다.
